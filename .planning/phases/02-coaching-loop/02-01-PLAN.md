Create `src/lib/coaching/audio-queue.ts` — a module-level singleton (NOT React state, per RESEARCH.md Pitfall 1). The AudioQueue class must:

1. Hold a private `AudioContext | null` and `currentSource: AudioBufferSourceNode | null`
2. `initialize(): AudioContext` — creates AudioContext with sampleRate 24000 if not exists. MUST be called inside a user gesture handler. Returns the context.
3. `async ensureRunning(): Promise<void>` — checks ctx.state, resumes if suspended (per PITFALLS.md Pitfall 2)
4. `async playChunk(base64Audio: string, sampleRate: number): Promise<void>` — decodes base64 PCM s16le to Float32Array, creates AudioBuffer, schedules on AudioContext timeline using `scheduledEndTime` for gapless playback. Exact decode pattern from RESEARCH.md Pattern 2: `atob → Uint8Array → Int16Array → Float32Array (divide by 32768)`
5. `enqueue(cue: AudioCue): void` — per D-05 two-tier priority: HIGH cues call `currentSource?.stop()`, reset `scheduledEndTime = ctx.currentTime`, flush `normalQueue = []`, set `isSpeaking = false`, then call `playCueNow(cue)`. NORMAL cues append to normalQueue if isSpeaking, else playCueNow.
6. Track `isSpeaking` boolean and `currentCueText` string. When speaking starts, call `useCoachingStore.getState().setIsSpeaking(true, cue.text)`. When cue completes (source.onended), call `setIsSpeaking(false)` and process next in normalQueue.
7. `stopAll(): void` — stops current source, clears queue, sets isSpeaking false
8. Export singleton: `export const audioQueue = new AudioQueue();`

Create `src/lib/coaching/cue-templates.ts` with the template library. Each template has: `key: string`, `priority: CuePriority`, `cooldownMs: number`, `text: (ctx: CueContext) => string`. Include at minimum these templates:

- `split_drift_up` — HIGH, cooldownMs 0: "Ease up on the rate, you're at {currentRate}. Split is drifting."
- `rate_too_high` — HIGH, cooldownMs 0: "Rate's at {currentRate}, bring it down to {targetRate or currentRate-2}."
- `rate_too_low` — NORMAL, cooldownMs 30000: "Pick up the rate a bit, you're at {currentRate}."
- `pace_on_target` — NORMAL, cooldownMs 60000: "Nice split, hold it."
- `halfway` — NORMAL, cooldownMs 0 (fires once): "Halfway. {distanceM}m in, {currentSplitStr} split."
- `session_start_cue` — NORMAL, cooldownMs 0: "Alright {userName}, let's go. Nice and steady."
- `encouragement_interval` — NORMAL, cooldownMs 120000: "Good rhythm. Keep it steady."

Export type `CueTemplate` and the `templates` array.

Create `src/lib/coaching/stroke-processor.ts` — a module-level singleton. The StrokeProcessor class must:

1. Maintain a `window: StrokeReading[]` (last 20 readings max, shift oldest when full)
2. `processReading(reading: StrokeReading): CoachingTrigger | null` — adds reading to window, runs threshold checks, returns a trigger if detected or null
3. Threshold checks (per RESEARCH.md Pattern 5):
   - `split_drift_up`: avg splitMs of last 8 readings increased >5000ms over the first reading in window → HIGH
   - `rate_too_high`: strokeRate > targetRate+4 for 5+ consecutive readings → HIGH
   - `rate_too_low`: strokeRate < targetRate-4 for 5+ consecutive readings → NORMAL
   - `pace_on_target`: splitMs within ±1000ms of target for 10+ consecutive readings → NORMAL
   - `halfway`: distanceMeters crosses half of targetDistance (fires once per session)
4. `setTargets(targetRate?: number, targetDistance?: number): void` — set from check-in data
5. `reset(): void` — clears window and fired-once flags. MUST be called at session start (per RESEARCH.md Pitfall 3)
6. Build `CueContext` from current window state for template slot-filling: compute `currentSplitStr` by formatting splitMs as "M:SS", `elapsedMin` from reading.elapsedTimeMs / 60000
7. Export singleton: `export const strokeProcessor = new StrokeProcessor();`

Create `src/lib/coaching/cue-router.ts` — a module-level singleton. The CueRouter class must:

1. Hold `cooldowns: Map<string, number>` tracking last-fired timestamp per trigger type
2. `route(trigger: CoachingTrigger): void`:
   - Check cooldown: if template exists for trigger.type, look up template.cooldownMs. If cooldownMs > 0 and (now - lastFired) < cooldownMs, skip (unless priority HIGH per D-06: HIGH bypasses cooldown)
   - If template found: fill template with trigger.context, create AudioCue with `crypto.randomUUID()` id, call `audioQueue.enqueue(cue)`. This is the pre-computed path (<500ms per COACH-02).
   - If no template found: store trigger in `pendingLlmTriggers` array for the LLM path (Plan 03 will consume this). Do NOT call Claude API from here — that happens in the API route.
3. `setMinCooldownMs(ms: number): void` — default 30000 per D-06
4. `reset(): void` — clears cooldowns map. Called at session start.
5. Export singleton: `export const cueRouter = new CueRouter();`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client AudioQueue -> Cartesia WS | API key used client-side for pre-computed cue path |
| Client -> Supabase | Session data writes cross auth boundary |
| StrokeReading -> StrokeProcessor | BLE data enters coaching pipeline |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | StrokeProcessor | mitigate | StrokeProcessor inherits validated StrokeReading from Phase 1 pm5-parser.ts validateStrokeReading(). No additional validation needed — corrupt data already rejected at BLE boundary. |
| T-02-02 | Information Disclosure | audio-queue.ts | accept | Cartesia API key exposed as NEXT_PUBLIC env var for client-side pre-computed path. Acceptable: key is rate-limited per Cartesia account, no PII transmitted, and server-side proxy adds latency exceeding COACH-02 <500ms target. |
| T-02-03 | Elevation of Privilege | Supabase sessions table | mitigate | RLS policies enforce auth.uid() = user_id on both SELECT and INSERT. Users cannot read or write other users' sessions. |
| T-02-04 | Elevation of Privilege | Supabase coach_memory table | mitigate | RLS policies enforce auth.uid() = user_id on SELECT, INSERT, and UPDATE. Unique constraint on (user_id, key) prevents unbounded row growth. |
| T-02-05 | Denial of Service | AudioQueue normalQueue | accept | No queue size limit. Acceptable for single-user PWA — cue generation rate is bounded by stroke frequency (~0.4 Hz) and cooldown timers (30s minimum). |
</threat_model>
