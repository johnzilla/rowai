<objective>
Complete the coaching loop with post-session debrief, session data persistence, and coach memory writes. When the user confirms "Done rowing?", the coach immediately delivers a voice debrief, then a summary card appears. Session data and coach memory are saved to Supabase. The "Done" button resets state and returns to the check-in screen.

Purpose: This closes the coaching loop. The debrief is the last thing the user hears each session — it reinforces the coaching relationship and creates the data foundation (POST-02, POST-03) that Phase 3's memory layer will consume.

Output: New summary card component, updated lifecycle hook with debriefing phase, session store extension, session page update.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| useSessionLifecycle -> /api/coach | Debrief intent (memory extraction embedded in response) |
| useSessionLifecycle -> Supabase | Session data and coach memory writes |
| SessionSummaryCard -> coaching-store | Reads session summary (client-side only) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-14 | Tampering | useSessionLifecycle.confirmEnd | mitigate | Session summary computed from stroke processor accumulators (not user input). Supabase write uses RLS (auth.uid() = user_id) so user cannot write sessions for others. |
| T-02-15 | Information Disclosure | coach memory extraction | accept | Claude may generate unexpected memory entries. All entries go through RLS-protected upsert. No PII exposure to other users. Entries visible only to the user who generated them. |
| T-02-16 | Denial of Service | confirmEnd debrief flow | accept | Debrief makes 1 API call to /api/coach (memory extraction is embedded in the debrief response, not a separate call) + 1 TTS call. Acceptable for post-session flow where latency is not critical. No retry loop — if debrief fails, summary card still shows with stats. |
</threat_model>
