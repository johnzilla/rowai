<objective>
Build the pre-session check-in screen and integrate mid-session coaching controls into the existing session page. The check-in collects energy/time via tap buttons, triggers a voice greeting via LLM+TTS, and navigates to the session. The session page gets a coaching indicator, mid-session tap controls, and the useCoachingSession hook that wires StrokeProcessor -> CueRouter -> AudioQueue.

Purpose: This is where the user first experiences the coach. The check-in sets the relational tone (D-01), and the mid-session controls give the user agency during rowing (D-09). The coaching pipeline hook connects all Plan 01 service modules to the live session.

Output: New check-in route + 4 new components + 1 hook + session page update.
</objective>

- Renders a bottom bar with 3 large tap buttons: "Too Hard", "Push Me", "I'm Good"
- Buttons are always the same 3 options (D-12: fixed, not context-adaptive)
- Touch targets: minimum 48px height, full width divided into 3 columns, thumb-reachable
- On tap: 
  1. Disable the tapped button briefly (300ms debounce) to prevent double-tap
  2. Call `fetch('/api/coach', { method: 'POST', body: JSON.stringify({ intent: mapButtonToIntent(button), sessionContext: buildSessionContext() }) })` where mapButtonToIntent maps: "Too Hard" -> "too_hard", "Push Me" -> "push_me", "I'm Good" -> "im_good"
  3. Stream the SSE response text, buffer complete, then call `fetch('/api/tts', ...)` and pipe audio to `audioQueue.playChunk()` (same pattern as check-in)
  4. `buildSessionContext()` reads current metrics from `useSessionStore.getState()` — rate, splitMs, watts, elapsedMin, distanceM
- Styling: fixed bottom bar, bg-gray-900 border-t border-gray-800, safe area padding (pb-safe-bottom)

Create `src/hooks/useCoachingSession.ts` — the coaching pipeline wiring hook:
- Subscribes to `useSessionStore` `latestReading` changes
- On each new reading (when `isSessionActive` is true):
  1. Call `strokeProcessor.processReading(reading)`
  2. If a `CoachingTrigger` is returned, call `cueRouter.route(trigger)`
  3. CueRouter internally calls `audioQueue.enqueue()` for pre-computed cues
- On session start (`isSessionActive` transitions to true):
  1. Call `strokeProcessor.reset()` and `cueRouter.reset()` (per RESEARCH.md Pitfall 3)
  2. Call `audioQueue.ensureRunning()`
  3. Set targets from coaching store: `strokeProcessor.setTargets(targetRate, targetDistance)` based on check-in session type if available
  4. Fire the `session_start_cue` via cueRouter
- On session end (sessionPhase transitions to 'ending' and user confirms): do NOT call endSession() yet — Plan 04 handles the debrief transition
- Must NOT block the React render cycle — stroke processing is synchronous and fast (<1ms)
- Returns: `{ isCoachingActive: boolean }` (true when pipeline is running)
