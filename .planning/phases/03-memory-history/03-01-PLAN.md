```typescript
function getSupabaseFromRequest(request: Request) {
  return createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll() {
          // Parse cookies from the request Cookie header
          const cookieHeader = request.headers.get('Cookie') ?? '';
          return cookieHeader.split(';').map((c) => {
            const [name, ...rest] = c.trim().split('=');
            return { name: name ?? '', value: rest.join('=') };
          }).filter((c) => c.name);
        },
        setAll() { /* read-only in route handler */ },
      },
    }
  );
}
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> /api/coach | Client sends intent + session context; route reads user identity from auth cookies |
| /api/coach -> Supabase | Route queries sessions/memory scoped by RLS to authenticated user |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | memory-snapshot.ts | mitigate | RLS policies on sessions and coach_memory tables enforce user_id = auth.uid(). Supabase client created from request cookies ensures user can only read their own data. |
| T-03-02 | Spoofing | route.ts getSupabaseFromRequest | mitigate | Supabase auth.getUser() validates the JWT from cookies server-side. No user ID is accepted from request body -- always derived from authenticated session. |
| T-03-03 | Tampering | route.ts intent field | accept | Intent is validated against ALLOWED_INTENTS allowlist. Session context is used only for prompt construction, not data writes. Low risk. |
| T-03-04 | Denial of Service | memory-snapshot.ts | mitigate | Queries are bounded: limit(5) for sessions, limit(20) for memory. Snapshot assembly is O(1) bounded. Try/catch ensures LLM call proceeds even if Supabase is slow/down. |
</threat_model>
