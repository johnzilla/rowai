<objective>
Add offline resilience to session and memory writes so no workout data is lost when the network is unavailable.

Purpose: A rower finishes a session in their garage with spotty WiFi. Without this, their session data vanishes. With this, it silently caches to localStorage and syncs next time the app loads or goes online. Per D-07 and D-08.

Output: `offline-cache.ts` (localStorage queue + sync), updated `session-writer.ts` (fallback on write failure), sync trigger in layout.
</objective>

```typescript
async function writeSessionDirect(data: SessionWritePayload): Promise<boolean> {
  const supabase = createClient();
  const { error } = await supabase.from('sessions').insert({
    user_id: data.userId,
    started_at: new Date(data.startedAt).toISOString(),
    ended_at: new Date(data.endedAt).toISOString(),
    duration_s: Math.round((data.endedAt - data.startedAt) / 1000),
    total_meters: data.totalMeters,
    avg_split_ms: data.avgSplitMs,
    avg_watts: data.avgWatts,
    avg_stroke_rate: data.avgStrokeRate,
    energy_level: data.energyLevel,
    session_type: data.sessionType,
  });
  return !error;
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage | Untrusted storage on user device; data could be tampered with |
| localStorage -> Supabase | Cached data replayed to Supabase on sync |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-05 | Tampering | offline-cache.ts localStorage | accept | User can only tamper with their own data. RLS on Supabase enforces user_id = auth.uid() so tampered writes for other users will be rejected. Risk is user corrupting their own session data, which is low value. |
| T-03-06 | Information Disclosure | localStorage | accept | Session data (distance, split, watts) is not sensitive PII. No credentials stored in cache. Single-user device assumption for PWA on personal phone. |
| T-03-07 | Denial of Service | flushPendingWrites | mitigate | Queue is bounded by practical usage (1-2 sessions per day). If localStorage is corrupted/unparseable, catch block logs error and clears the queue to prevent infinite retry loops. |
</threat_model>
