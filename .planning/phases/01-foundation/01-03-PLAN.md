```typescript
export function useSessionLifecycle() {
  // D-08: auto-start on first stroke detection
  // Watch latestReading.strokeState from useSessionStore.
  // When strokeState transitions from 0 (idle) to non-zero (drive/recover) AND isSessionActive=false,
  // call store.startSession().

  // D-09: auto-end after 30s of zero strokes
  // Track lastStrokeAt in a ref. When a reading arrives with strokeState=0 (or strokeState is idle),
  // start a 30s countdown timer. If a stroke arrives before 30s, cancel the timer.
  // After 30s of no strokes, set sessionPhase to 'ending' to trigger SessionEndPrompt.

  // D-10: no pause state — if user rows again while prompt is showing, cancel the ending prompt
  // and set sessionPhase back to 'active'.

  // Returns: { showEndPrompt: boolean, confirmEnd: () => void, dismissEnd: () => void }
}
```

Implementation detail for idle detection:
- `lastStrokeAt` ref updated on every reading where strokeState > 0
- `useEffect` that runs a `setInterval` every 5s checking if `Date.now() - lastStrokeAt.current > 30000`
- On 30s idle: set `sessionPhase = 'ending'` via store
- On new stroke while `sessionPhase === 'ending'`: set `sessionPhase = 'active'` (D-10 — no pause)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User gesture → BLE requestDevice | Chrome enforces user gesture for BLE dialog |
| BLE event data → React state | StrokeReading flows from PM5Service to Zustand to UI |
| Session page → Supabase auth | Auth guard on page mount |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | BleConnectButton / BLE connect | mitigate | Connect is triggered only from user gesture (onClick). navigator.bluetooth.requestDevice() is filtered by PM5_SERVICE_UUID. User sees device name in Chrome's native chooser — cannot be spoofed by app UI. |
| T-03-02 | Denial of Service | useSessionLifecycle 30s timer | accept | Timer runs in browser, single user. No server-side resource impact. Timer is cleared on unmount. |
| T-03-03 | Information Disclosure | MetricDisplay shows live rowing data | accept | Data displayed is real-time sensor readings from the user's own PM5. No third-party can see the screen. No data is transmitted to server in this plan (session save is Phase 2). |
| T-03-04 | Elevation of Privilege | Session page auth guard | mitigate | Middleware (Plan 01) redirects unauthenticated users before page renders. Page-level guard (belt-and-suspenders) also checks user on mount. Double-protected. |
</threat_model>
